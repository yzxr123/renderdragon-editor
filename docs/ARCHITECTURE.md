# 架构与算法

## 数据流

主页面加载颜色协议、schema、文件系统、材质注册表和工作区，再初始化参数编辑器与 iframe 画板。`RenderDragonBridge` 连接两个界面；画板使用同源父页面 API，不向外部服务发送图像。

`seed-data.js` 包含群系与参数默认值；`data/template/` 提供贴图源文件。构建脚本生成 gzip + TAR + Base64 的模板包，并将共享颜色模块、画板 CSS 与脚本内联到 `srcdoc` 文档，从而保留离线运行方式。源码保留在独立文件中，避免维护转义的大字符串。

## 写时复制与最小导出

`fs-core.js` 将浏览器目录句柄和内存句柄统一为相似接口。`workspace-io.js` 的 `WorkspaceStore` 保存只读基线、覆盖层 `overlay` 和删除集合 `deleted`。导入文件先建立句柄索引，访问时才读取。原资源包不写回。

JSON 比较忽略缩进和属性顺序；与基线相同的修改会被撤销。修改共享参数时为当前群系生成独立标识并更新引用，避免意外影响其他群系。事务失败会恢复文件覆盖、删除集合、路由、生成参数与目录索引。

导出器从实际修改开始，补齐群系绑定、材质 Texture Set、引用图像和必要索引；过滤编辑器内部元数据，再建立新的 manifest。每次新导出生成独立 UUID。恢复参数只恢复参数，不清除纹理编辑；单材质另存不会把全工作区标记为已导出。

## PBR 估计流程

实现见 `assets/pbr-algorithm.js`，入口为 `generate` 与 `generateChannel`。

1. 按目标分辨率准备源图像，缩小时在 alpha 加权后平均颜色，避免透明边缘引入黑边。
2. 以 `0.2126R + 0.7152G + 0.0722B` 计算亮度，统计饱和度、亮度方差、梯度与局部变化。
3. 以邻域中值和平滑系数抑制污渍，把稳定的明暗结构用于高度估计；灰白低对比材质可增强结构信号。
4. 从高度梯度构造法线，结合像素边界、倒角、几何深度和细节强度生成表面起伏。
5. 用亮度、饱和度和结构信号启发式估计粗糙度、金属度与自发光。固定坐标散列提供可复现的细节，不使用随机结果。
6. 使用近似 GGX 光照、sRGB/线性转换和 ACES 曲线生成预览。

这是单图像推断，不能唯一确定物理材质；高亮不一定代表金属或发光。用户应检查并手动调整输出。算法配置只接受已知字段、正确类型和有限数值；图像与输出大小有保护上限。

## MERS 与 FIO

`mers-codec.js` 将金属度、自发光、粗糙度和次表面量依次打包到 RGBA。A 是材质数据，不是用于显示的透明度。`png-codec.js` 直接处理 PNG 数值通道，避免 Canvas 的预乘透明度丢失 A=0 时的 RGB 数据；显示预览另行设置为不透明。

`texture-targets.js` 的 FIO 为四分区：左上基色、右上材质数据、左下法线、右下检测标记。材质 R 保存 `255 - roughness`，G 保存金属度，A 保存 `255 - emissive`；导入的未知 B 数据原样保留。检测完整标记后才拆分，避免把普通四宫格误裁切。FIO 不携带完整 MERS 的次表面信息，两者转换存在能力差异。

## 缓存与界面

材质注册表追踪 Texture Set 与图像引用，WeakMap 缓存按根目录对象隔离。画板以作业序号区分异步载入，避免旧任务覆盖新纹理；批量生成可在 Worker 中执行。主题、布局与用户配方保存在浏览器本地，工作区修改则应显式下载保存。

## 兼容边界

文件名改为 kebab-case，模块别名和关键状态变量改为语义名称；JSON 格式字段、贴图路径、桥接 API、本地存储键维持兼容。游戏格式版本来自原工程，未以离线网页测试冒充游戏兼容性结论。
